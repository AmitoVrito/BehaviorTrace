# results_table.csv - provenance

Generated by `notebooks/colab/E2_1_export_results.ipynb`, which reads the saved score
files from Drive and recomputes every value with the repo's own metric functions
(`behaviortrace.eval.metrics`). Columns: seed, table, method, value, lo, hi (bootstrap 95% CI where
applicable), chance, ceiling, n.

Tables:
- `overall` and `early_nonzero` (step level): all 3 seeds, from each run's `attribution_scores.json`
  + `ground_truth.jsonl`. Complete.
- `mp_raw` and `mp_residualized` (rollout level, minimal-pair): SEED 2 ONLY in this CSV.

Known gap (seeds 0/1 rollout level): the per-rollout ROW files were first saved AFTER the
pre-registered seed-0 and seed-1 minimal-pair runs, so `minimal_pair_rows_ckpt0_gen0.json` and
`ckpt1_gen1.json` do not exist. Those seeds' numbers are read from the saved per-seed run notebooks
under `notebooks/colab/runs/` (each a fixed record of one executed draw):
- seed 0 pre-registered (N_REPEATS=6): `E2_1_per_rollout_mp_seed0.ipynb` - residualized GAS 0.486
  [0.415,0.570], norm 0.726 [0.655,0.787], plain 0.477 [0.398,0.558], fluency RAW 0.776; 87 matched pairs.
- seed 1 pre-registered (N_REPEATS=6): `E2_1_per_rollout_mp_seed1.ipynb` - residualized GAS 0.624
  [0.548,0.700], norm 0.524 [0.428,0.615], plain 0.602 [0.518,0.684], fluency RAW 0.838; 86 matched pairs.
- diagnostic draws: `E2_1_per_rollout_mp_ckpt0_gen100.ipynb` (GAS resid 0.446) and
  `E2_1_per_rollout_mp_ckpt1_gen101.ipynb` (GAS resid 0.526); their row files
  (`minimal_pair_rows_ckpt0_gen100.json`, `ckpt1_gen101.json`) are under `data/results/runs/` and in this CSV.
- seed 2 pre-registered: `E2_1_per_rollout_mp_seed2.ipynb`; its rows are saved
  (`minimal_pair_rows_ckpt2_gen2.json`) and in this CSV.
We do NOT re-run seeds 0/1 (a fresh draw would differ, which is the C6 instability point).
The two diagnostic draws are now IN the CSV (tables mp_raw_diag / mp_residualized_diag, rows
0_gen100 and 1_gen101): residualized GAS 0.4459 (ckpt0/gen100) and 0.5264 (ckpt1/gen101), matching
the commit-cited values.

GOING FORWARD: save each executed run notebook with the SEED in its filename (e.g.

CI columns (lo/hi): the PAPER cites the run-notebook bootstrap CIs for ALL seeds (one procedure; the
pre-registered 0.15 width rule was applied with that procedure). The export bootstrap was FIXED to
the same cluster bootstrap (resampled groups kept separate, per-seed rng = default_rng(GEN_SEED)) and
against the 0.01-per-endpoint tolerance we set: norm-only PASSES (seed-2 residualized [0.684,0.790]
vs notebook [0.684,0.789], within 0.001); GAS NARROWLY FAILS (lower end 0.561 vs 0.573, off by
0.012, just over the 0.01 tolerance), consistent with resampling noise at 600 resamples. It is not
byte-exact because the notebook consumes its rng through other calls first (draw-order). So the PAPER
cites the run-notebook CIs throughout; the CSV CI columns are a consistent but NON-IDENTICAL
recomputation. CSV POINT estimates are authoritative and match the runs. (The export now uses 5,000
resamples, so a future refresh should AGREE MORE CLOSELY - not guaranteed to pass, since the
notebook's 0.573 itself carries ~0.01 noise from only 600 resamples, so the two could still differ
by more than 0.01; the committed CSV above is the 600-resample run.)

## Offline reproduction (Drive-free): `data/results/runs/`

To let the export notebook rebuild `results_table.csv` without Google Drive, the per-seed score files
are mirrored under `data/results/runs/<run_name>/`, matching the notebook's
`RUN_TMPL = E2.1_rebuild__qwen-1.5b__grpo__seed{seed}__v3` plus the `runs/` convention. Point the
export notebook's artifacts root at `data/results` (instead of the Drive root) and it resolves them.

Present now (committed, ~12 MB total), four files per seed in each
`data/results/runs/E2.1_rebuild__qwen-1.5b__grpo__seed{N}__v3/`:
- `attribution_scores.json` - step-level per-rollout scores for every method (the `seed` /
  `run_name` fields confirm the mapping).
- `ground_truth.jsonl` - step-level GT. Mapped by matching unique rollout-id count to each seed's
  `gt_size` (1509 / 1497 / 1383 for seed 0 / 1 / 2); the Drive export dumps held several runs'
  GT logs, so this content match (not the filename) is what fixes the seed.
- `token_level_cos_temp0.9.json` - Table 4; mapped by `mean(vs_ctx)` = +0.230 / +0.114 / +0.295.
- `minimal_pair_rows_*.json` - rollout level: `ckpt2_gen2` (seed 2 pre-reg) plus the two diagnostic
  draws `ckpt0_gen100` (seed-0 folder) and `ckpt1_gen101` (seed-1 folder). Seeds 0/1 pre-reg rows
  predate row saving and survive only as the saved run notebooks
  `E2_1_per_rollout_mp_seed0.ipynb` and `E2_1_per_rollout_mp_seed1.ipynb`.
